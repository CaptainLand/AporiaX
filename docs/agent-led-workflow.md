# Agent 主导的工作流程

## 验收边界

- 当任务进入交付阶段时，Harness 不因文件数、计划步骤或工作区存在 package.json 自动执行测试或启动 Review。
- 当主 Agent 请求独立检查时，Harness 只执行这次明确选择且说明相关性的命令；候选脚本不是必执行项。
- 当检查失败、环境不可用、证据过时或审查未完成时，允许交付已有文件，同时附带真实验证状态，不签发虚假的通过结论。
- 当重复获取相同结果时，提醒调整策略，不单凭重复次数终止整项任务。
- 安全权限、拒绝授权、危险删除、未知副作用重放核对、持久化失败和用户停止不受工作流程策略影响。

- [x] 以真实执行记录形成交付状态，保留失败和过期证据。
- [x] 将重复结果的硬终止改为分级提醒。
- [x] 验证独立 HTML + 临时服务器、已有 HTML、无关根目录测试、失败/未执行/过期检查、显式 Review 与安全边界。

主 Agent 负责根据用户目标选择检查；Harness 负责执行授权、证据记录和诚实展示。已有的并发、子 Agent 轮次和网络空闲超时上限仍用于控制资源，本次不取消这些上限。模型可重新委派后续工作；不将资源上限改成无限循环。
