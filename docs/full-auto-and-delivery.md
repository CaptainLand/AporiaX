# 全自动审批与简洁交付（0.7.2 本地补丁）

## 可见变化

- 新任务默认 **全自动**，不要求先批准一次。旧任务的默认 `sandbox-auto` 映射为全自动；明确选择的手动、智能模式保持不变。可在新建任务或任务设置中切换，设置变更从下一次运行生效。
- 全自动会批准被允许工具发起的命令、npm start/dev、构建/本地打包、安装依赖、浏览器操作、外部文件读取及网络/发布操作。明确拒绝的工具仍拒绝。
- **这是高权限信任，不是 OS 隔离。** 可识别的工作区外删除、工作区根目录删除、不明目标删除，以及异常恢复时不确定/重复的副作用仍需确认。路径会核对真实位置，防止通过目录链接绕过。任意脚本/MCP 可以间接执行删除；仅凭命令名称和参数无法可靠阻止，不能据此声称整个电脑已受到删除保护。
- 最终文件交付和已确认可用的预览交付采用“一句结果 + 可点击链接 + 必要限制”。普通对话、诊断和运行中的阶段说明不截断、不额外调用模型重写。
- 不会凭空生成文件地址、预览端口，或把已停止的进程称为可访问服务；这次没有改变任务结束时托管进程的清理策略。

## 验证与交付分离

- 仅文档或新建独立 HTML 交付不再直接套用项目根目录的 npm 单元测试。源代码改动仍发现项目验证脚本；显式执行过的验证证据保留。
- 直接用户消息如“先别测试了，直接交付吧”可跳过可执行测试，保留独立静态复核及已发现的问题；结果标为“已交付·未验证”，不伪称测试通过。该指令只解析短的直接用户请求，不读取项目文档、工具结果或模型文字来获得豁免。“恢复测试”取消豁免。
- 验证启动失败且没有实现审查问题时返回 `blocked`，界面显示“验证受阻·实现已保存”，可以重试；测试断言失败、关键审查问题、持久化失败不因此降级成成功。
- 沙箱复制/同步在 Electron 中改用 `original-fs`，将其他项目的 `app.asar` 当作普通文件，不再通过虚拟目录 API 递归复制。

## 验证记录

- `npm run test:delivery-auto`：100 次无首次审批、删除边界与目录链接、主循环全自动接线、相关测试发现、用户豁免/静态复核保留、最终提示无额外模型调用、实际 React 三模式切换、真实 Electron 的 ASAR 工作区命令执行。
- 另运行主循环、恢复 P1、工具权限/分发、自检、执行模式、效率与插话回归，及文件超链接的真实浏览器交互。
- 使用模拟模型，不调用付费 API；未执行真实网络发布或破坏性删除来验证自动批准。文件/服务链接策略通过进入模型请求的规则与已有链接交互测试验证，不能保证任意第三方模型每次均完全遵循文案要求。
- 无 GitHub 提交、推送或线上部署。
