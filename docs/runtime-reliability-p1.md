# 核心运行可靠性：第一优先级修复

本次不改变发布版本，不调整模型价格、账号、手机端或部署配置。

## 验证与复核

- 验证记录绑定当前变更集合的版本签名、规范化命令和工作目录。
- 同一命令以后一次结果为准；其他命令成功不会掩盖当前版本的失败。
- 保留选择相关验证命令的策略，不强制运行所有发现的脚本。未运行的候选不是通过的检查。
- 读取证据包含实际内容哈希和读取区间；支持合并多次分页读取，至少覆盖改动及上下文。子 Agent 输出截断会同步缩小有效证据范围。
- 分段验证失败反馈包含实际命令、退出码和输出摘要；环境阻塞直接报告，重复无进展会停止。正常新增读取证据和代码变化不会被当成重复。

## 模型响应

保留 finish reason，处理末尾没有换行的 SSE 数据。不完整流、输出长度截断、无效工具参数不能进入完成或执行工具阶段。收到部分响应后不会悄悄自动重试该请求。

## 检查点与恢复

SQLite 增加兼容旧库的检查点和操作表，关键状态使用 WAL + FULL 同步。

检查点保存主任务及各子任务的计划、状态、公开工作摘要、文件版本、验证证据和待审批状态。排队任务绑定入队时的异步上下文，防止日志写入另一个任务。

有副作用的原生工具及 MCP 调用执行前先写入 started，返回后写入 confirmed；执行异常或超时记为 uncertain。写入失败可见，并停止后续执行。恢复副本保存完成之后才标记原任务已被恢复。

恢复时：

1. 使用检查点和操作凭据重建工作上下文。
2. 重新检查实际文件、进程和外部服务状态；旧验证结果不是对现状的保证。
3. 不确定的操作，以及与已确认操作相同的重复请求，必须逐次确认。
4. 不继承旧审批。旧版本没有操作凭据的任务采取保守核对策略。

恢复不是让断开的模型请求、操作系统进程或内部推理原地复活。未知外部操作无法保证 exactly-once，必须核对实际结果。本次不自动重启服务器、不自动重新发布 PR。

## 验证

新增 npm run test:priority-one，覆盖版本失效、失败覆盖成功、分页证据、响应截断、落盘失败、审批拒绝、并发上下文归属和测试子进程异常终止后的恢复。

这些是离线及模拟故障测试，不调用付费模型、不访问真实外部写入接口，也不等同于对实际机器断电或磁盘硬件故障的保证。
