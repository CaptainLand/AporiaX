# Windows 公共发行

从下一次发行起，仅构建、上传 Windows x64 安装版。每个正式版本公开四个文件：

- `AporiaX-Setup-<版本>-x64.exe`
- 对应的 `.exe.blockmap`
- `latest.yml`
- `SHA256SUMS-<版本>.txt`

校验清单包含安装包、blockmap 和更新元数据三项，不包含便携包。GitHub 发布及国内镜像均采用这一清单；仍需验证实际安装包内容、源码与更新摘要，不因减少文件而取消校验。

GitHub 已发布的历史版本保持原样，既有便携包、标签、校验清单和用户数据不删除、不覆盖、不重新打包。腾讯云公开下载目录按下述“仅保留最新版”策略处理，不要求永久保留历史安装包。旧便携版用户后续可从新版发布页获取安装版迁移；不替用户自动安装。

历史或私有构建需要验证便携包时，可显式使用 `--include-portable`。此选项不改变公共打包与上传的安装版默认策略，也不触发上传。私测便携构建脚本不属于公共发行入口。

## 每次正式发布的联动流程

用户于 2026-10-23 确认：今后每次发布新版本，一并更新官网入口，随后清理腾讯云旧版下载文件，仅保留最新版。此流程不触发定时发布，也不把“仅本地打包”视为线上发布授权。

1. 构建并验证最新版安装包、源码一致性、SHA256 与更新清单中的大小和 SHA512；只发布安装版。
2. 上传 GitHub Release 和现有腾讯云镜像，核对远端文件摘要后公开 Release、更新相应通道清单；不要覆盖旧 GitHub 附件。
3. 同步更新官网集中管理的版本信息、下载按钮、页脚版本与发布说明链接。先核对实际线上页面及本地源码，避免部署其他未发布改动。入口与异步模块的内容哈希引用必须匹配，不能只重命名单个入口模块。
4. 实际验证官网桌面和手机宽度下的版本及下载地址、账户与社区相邻路由、静态资源加载，以及公网安装包和更新清单可访问。适用时验证旧桌面端能够发现新版。不以仅构建通过代替浏览器验证。
5. 以上检查全部通过后，再清理腾讯云公开下载目录 `/var/www/aporiax-beta/downloads` 的旧版安装包、便携包、对应 blockmap 和旧校验清单。保留最新版安装包、blockmap、版本校验清单，以及仍使用的 `latest.yml` / `preview.yml` / `rc.yml`；所有保留的活动通道必须指向有效最新版。
6. 清理前重新解析并校验目录和每个文件的绝对路径，拒绝符号链接、未知文件和目录；采用明确文件清单逐项删除，不使用递归删除或宽泛通配符。持有与镜像发布共用的互斥锁，检查新旧文件状态未变化，保存删除清单审计。
7. 清理后再次校验最新版摘要和公网下载，记录释放空间、剩余空间和实际删除范围。历史直链将不再提供旧包；历史版本可从 GitHub 重新同步。

任何验证未通过，不删除旧下载文件，并明确报告未完成项。仅保留最新版的策略不适用于 GitHub 历史 Release、Web 历史部署、运维备份、数据库、账号资料、服务器暂存目录或其他存储；不得顺带清理这些内容。
