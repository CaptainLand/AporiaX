# AporiaX v0.6.5 — Git and GitHub workflow slice

This slice is stacked on the v0.6.5 execution and smart-permission foundation.

## Native workflow tools

- `git_log` reads recent history.
- `git_stage` stages only explicit workspace-relative paths.
- `git_commit` commits already staged changes and never silently stages the repository.
- `git_create_branch` validates and creates a new branch.
- `git_pull` requires a clean working tree and defaults to `--ff-only`; explicit rebase is supported.
- `git_push` supports normal branch pushes and optional upstream setup; force push is intentionally unsupported.
- `github_pr_create` creates a pull request through the authenticated GitHub CLI.
- `github_pr_view` reads PR metadata.
- `github_pr_checks` reads CI/check results and surfaces failures as evidence.

## Permission boundary

Read-only Git/PR inspection is automatically available under the normal read policy. Repository mutations and remote writes stay behind explicit approval. Builder agents do not receive remote Git/GitHub write authority.

GitHub credentials remain inside the user-authenticated `gh` process and are not serialized into model context.
