# AporiaX 1.0.0 本地发布验证

日期：2026-10-15 · Windows x64 · Node.js 22.19.0 · Electron 39.8.10。

## 安装事件与撤回

初次 1.0.0 已撤为 GitHub 草稿，官网及 latest / preview / rc 下载通道恢复 RC5.2。此前“实际打包程序启动”仅测试了 win-unpacked 目录，在安装/便携环境变量下启动，并不等于运行实际 Setup 安装后验收；这一覆盖缺口不能用原测试通过来代替。

事件只读检查发现：发布的 Setup 与 Portable 中 app.asar 均为 123,985,786 bytes，SHA-256 为 `5580fb686c5846e7e30b673a8fd15ecc293fc8530e11019b5b3c5c1d312f8154`；本机原安装中的文件仅 54,525,952 bytes，且与完整文件的相同长度前缀逐字节一致，package.json 位于缺失区域，无法读取。这直接解释了应用未加载、落入 Electron 默认页，以及严格身份核对拒绝整理。临时盘仅余约 247 MB，空间不足是重点嫌疑，但安装当时日志不足，尚不能把截断唯一归因于它。

按用户要求，安装钩子及兼容性测试恢复 RC5.2 的原目录覆盖方案；不加载副本整理脚本，不跨目录搬动程序。下文为撤回前的历史验证记录，不表示该包现在仍可发布。

### 回退与恢复后的验证

- 两个实际安装钩子与 `v1.0.0-rc.5.2` 完全一致；13 项原生目录定位／恢复检查通过。
- 在随机产品标识与隔离目录运行完整安装器升级：无 `/D` 更新原目录、歧义时中止、显式原目录修复及保留用户数据均通过。另用实际 Electron / ASAR / x64 原生依赖完整载荷重跑，安装后逐文件核对并真实启动 AporiaX 欢迎页通过。
- Windows x64 的 NSIS 安装观察到六个非 x64（ARM64）原生文件未落地，专项验收明确记录并只豁免这些不存在的外架构文件；应用归档、x64 文件及其他运行资源仍逐字节检查，不把该结果写成所有文件均安装成功。
- 独立重建目录 `.tmp/rollback-installer-1.0.0` 中 Setup 为 156,743,817 bytes，SHA-256 `7618e6584a802c9275c012e725a2ca65fc75b6f7e308797233ed0d60fd0e1bf0`。Setup 与 Portable 实际下载载荷均解压核对 785 个文件，与构建目录逐字节一致；下载包核对现已加入发布验证脚本。
- 经用户明确同意，本机仅修复八个程序文件，替换前留存备份；恢复后的安装目录全部 785 个载荷文件一致。用独立配置启动本机实际主程序，欢迎页、版本、登录域名及更新状态检查通过；没有修改真实对话、账户、工作区或登记。
- 原发布二进制保留取证，未在同版本公开资源上覆盖替换，也未重新上线回退包。
