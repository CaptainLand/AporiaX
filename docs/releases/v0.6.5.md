# AporiaX v0.6.5 — Execution & Coding Foundations

AporiaX 0.6.5 is planned as a focused Coding Agent infrastructure release. The release separates **permission decisions** from **execution isolation**, then builds Git/GitHub and LSP workflows on top of that boundary.

## Execution profiles

The target execution model has three explicit profiles:

- **Direct** — commands run in the real authorized workspace with host process and network authority. This is the fastest profile and relies on command-aware permissions, Evidence, and Anchor recovery.
- **Safe** — commands run in a temporary workspace copy and synchronize changes back only after conflict checks. This protects workspace mutations, but it is not an OS security sandbox and still has host process/network authority.
- **Isolated** — commands run in the Docker sandbox with OS-level isolation, a read-only root filesystem, bounded resources, and isolated networking according to the sandbox policy.

The execution profile answers **where an operation runs**. Permission policy separately answers **whether it may run automatically, requires approval, or is denied**.

## Smart permission foundation

The first 0.6.5 implementation slice adds deterministic command classification before approval:

- low-risk Git inspection and bounded build/test/lint/type-check commands can be recognized for automatic approval;
- dependency installation/removal, explicit network transfers, remote writes, and destructive workspace operations require approval;
- clearly system-destructive commands are denied at the policy boundary;
- an explicit `ask` tool policy can no longer be bypassed merely because a sandbox backend exists;
- unknown commands remain approval-gated in Direct and Safe profiles because both can exercise host authority; an Isolated profile may auto-run unknown commands unless a higher-risk rule matches.

The classifier is intentionally deterministic. Model reasoning may provide context later, but it must not replace hard safety rules.

## Next implementation slices

The remaining 0.6.5 work should land as reviewable follow-up PRs on top of this foundation:

1. wire the three execution profiles through task settings, Runtime, persistent processes, Builder verification, and Evidence;
2. add native Git write operations and GitHub branch/commit/push/pull/PR/CI capabilities behind the permission engine;
3. add a persistent LSP manager with diagnostics, definition, references, hover, document symbols, and workspace symbols;
4. unify long-running processes and LSP servers under task-scoped execution sessions;
5. add workspace trust and scoped secret/environment policies before expanding automatic host execution.

## Safety invariant

AporiaX should keep these concepts orthogonal:

```text
Tool Call
   ↓
Permission Engine      allow / ask / deny
   ↓
Execution Policy      direct / safe / isolated
   ↓
Execution + Evidence
   ↓
Review / Verify
   ↓
Anchor / recovery
```

This preserves the low-friction workflow of a modern Coding Agent without treating user approval as a substitute for isolation or recovery.
