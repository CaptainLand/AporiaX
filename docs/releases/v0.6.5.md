# AporiaX v0.6.5 — Execution & Coding Foundations

AporiaX 0.6.5 is a focused Coding Agent infrastructure release. It separates **permission decisions** from **execution isolation**, adds persistent native language intelligence, and completes the native Git/GitHub workflow from an ordinary folder to a reviewable pull request.

## Execution profiles

AporiaX now has three explicit execution profiles:

- **Direct** — commands run in the real authorized workspace with host process and network authority. This is the fastest profile and relies on Smart Permission, Evidence, and Anchor recovery.
- **Safe** — commands run in a temporary workspace copy and synchronize changes back only after conflict checks. This protects workspace mutations, but it is not an OS security sandbox and still uses host process/network authority.
- **Isolated** — commands run in the Docker sandbox with OS-level isolation, bounded resources, and sandbox networking policy. Selecting Isolated never silently falls back to Host.

Execution Mode answers **where an operation runs**. Permission policy separately answers **whether it may run automatically, requires approval, or is denied**.

## Smart Permission

0.6.5 adds deterministic command classification before execution:

- low-risk Git inspection and bounded build/test/lint/type-check workflows can be recognized for automatic approval;
- dependency installation/removal, explicit network transfers, remote writes, and destructive workspace operations require approval;
- clearly system-destructive commands are denied at the policy boundary;
- explicit tool-level `ask` policies cannot be bypassed because a sandbox backend exists;
- unknown commands stay approval-gated in Direct and Safe because both can exercise host authority, while Isolated may auto-run unknown commands unless a higher-risk rule matches.

The classifier is intentionally deterministic. Model reasoning may add context, but it does not replace hard safety rules.

## Persistent native LSP

AporiaX now keeps language-server sessions alive per task/workspace and exposes native semantic operations:

- `status`
- `diagnostics`
- `definition`
- `references`
- `hover`
- `document_symbols`
- `workspace_symbols`

TypeScript / JavaScript language intelligence is bundled. For supported external language servers, `lsp status` reports availability, source, installer, and managed state. If a server is missing, the Agent can request approval to install it through `lsp_install` instead of telling the user to install it manually.

Managed installation paths include:

- **Python** — Pyright in AporiaX-managed storage
- **Go** — gopls in AporiaX-managed storage
- **Rust** — rust-analyzer through rustup
- **C / C++** — clangd through winget on Windows, Homebrew on macOS, or apt-get on Linux

## Complete Git / GitHub Agent workflow

AporiaX can now progress from a normal workspace folder to a reviewable GitHub pull request through native tools:

1. `git_init`
2. `git_status` / `git_diff` / `git_log`
3. explicit `git_stage`
4. `git_commit`
5. `git_create_branch`
6. `git_remote_list` / `git_remote_add`
7. `git_pull` / `git_push`
8. `github_repo_create`
9. `github_pr_create`
10. `github_pr_view` / `github_pr_checks`

Behavior and safety boundaries:

- a normal folder can be initialized by the Agent with `git_init`;
- local Git lifecycle operations can run autonomously under workspace-write policy;
- staging requires explicit workspace-relative paths;
- commits use already-staged changes only;
- pull requires a clean working tree and defaults to fast-forward-only behavior;
- remote routing and writes remain approval-gated;
- force push is intentionally not exposed;
- GitHub credentials stay in the authenticated GitHub CLI process and are not serialized into model context.

## Known boundaries

- Windows x64 remains the packaged desktop target for this preview release.
- Safe protects workspace mutations but still uses host process/network authority; use Isolated when OS-level isolation is required.
- Persistent Host processes are supported in Direct/Safe. Isolated intentionally blocks silent Host fallback until persistent isolated-process support is implemented.
- Workspace Trust and more granular secret/environment policies remain follow-up work before broader automatic host execution.
- Scanned PDFs are detected as requiring OCR, but an OCR engine is not bundled yet.

## Safety invariant

AporiaX keeps permission, execution location, evidence, verification, and recovery as separate layers:

```text
Tool Call
   ↓
Permission Engine      allow / ask / deny
   ↓
Execution Policy      direct / safe / isolated
   ↓
Execution + Evidence
   ↓
Review / Verify
   ↓
Anchor / recovery
```

This preserves a low-friction Coding Agent workflow without treating user approval as a substitute for isolation, evidence, or recovery.
