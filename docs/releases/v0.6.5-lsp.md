# AporiaX v0.6.5 — Native LSP slice

This slice is stacked on the v0.6.5 execution and smart-permission foundation.

## Semantic tool surface

AporiaX adds one native `lsp` tool with persistent per-task language-server sessions and these operations:

- `status`
- `diagnostics`
- `definition`
- `references`
- `hover`
- `document_symbols`
- `workspace_symbols`

The tool uses workspace-relative paths and converts user-facing 1-based positions to standard LSP positions internally.

## Language servers

- TypeScript / JavaScript: bundled `typescript-language-server` + TypeScript.
- Python: `pyright-langserver` when installed on PATH.
- Rust: `rust-analyzer` when installed on PATH.
- Go: `gopls` when installed on PATH.
- C / C++: `clangd` when installed on PATH.

A language server is started once for the task/workspace and reused across LSP calls. Sessions are shut down at task completion.

## Verification model

LSP diagnostics are a fast semantic inner-loop signal after edits. They do not replace final compiler/build/test verification. The intended coding loop is:

```text
ripgrep/search -> locate
LSP -> understand
patch -> change
LSP diagnostics -> fast semantic feedback
build/tests -> prove
Review/Verify -> seal evidence
```

Language-server processes receive AporiaX's filtered Host environment so sensitive variables are not blindly inherited.
