# AporiaX 0.6.0 — Architecture Reconstruction / 架构重构

AporiaX 0.6.0 is a major release that turns the project from an accumulation of Agent features into a more explicit, testable, and extensible local Agent platform.

AporiaX 0.6.0 是一次大版本升级：它不只是增加功能，而是对渲染层、Harness Runtime、任务状态、能力系统、扩展体系、自检流程和沙箱执行进行了系统性重构。

## 中文更新说明

### 1. 核心架构重构

- 对话与运行状态迁移为原生 React UI，移除旧的 DOM enhancement islands。
- TaskStore 成为渲染层单一状态源，降低跨任务、重试和流式更新中的状态漂移。
- 新增纯 Harness Event Reducer 与 Run/Turn Coordinator，统一开始、暂停、停止、恢复、重试和完成生命周期。
- 将 Provider Streaming、Tool Permission、Native Tool Dispatcher/Executor、Workspace Runtime、Conversation Runtime、Subagent Loop、Self-check Evidence 与 Coordinator 拆为独立可测试模块。
- 流式输出采用批处理与延迟持久化，减少长回答中的渲染和磁盘写入压力。
- 新增 v0.6 Architecture Freeze Gate，阻止已经淘汰的状态桥接重新进入主路径。

### 2. 统一 Capability 系统

- 原生工具、Office、Browser、Skills、MCP 与扩展能力统一进入 Harness Capability Registry。
- Route 展示、权限说明、能力目录和前端扩展中心由同一份能力元数据驱动。
- 新增能力来源、作用域、审批策略、可观察信息与生命周期策略。
- 不再依赖只针对单一 Provider 或固定工具列表的散落硬编码。

### 3. Skill 与 MCP 扩展中心

- 新增中英文 Extensions Center，区分 Skill 与 MCP，支持发现、搜索、安装/配置、启停和来源策略。
- 内置 Frontend Review 与 Release Readiness Skill 模板。
- Skills 支持声明式发现、按任务激活、工作区隔离与受限指令加载。
- MCP 支持受信任的本地进程与远程 Server，并将工具按运行作用域注册进 Harness。
- 新增扩展生命周期策略与权限边界，第三方扩展默认需要用户理解其来源与能力。

### 4. 多 Agent 与自检升级

- 保留 Adaptive Agent Budget、Explore、Builder、Review、Verify、Curator 和 Witness 的职责边界。
- Builder 继续使用 Task Graph、Scope Lease、隔离 Git worktree 与冲突安全合并。
- 渐进式 Review/Verify 与文件版本绑定；旧版本检查结果不能为新修改错误背书。
- 可在符合条件时并行使用最多两个受控检查 Worker，减少自检独占长任务时间。
- 最终封印只接受当前版本的有效 Review 与 Verify Evidence，并强化失败验证传播。
- Curator 自主判断本轮证据是否值得沉淀到 Project Understanding，不再机械地每轮写入。

### 5. Witness、恢复与上下文隔离

- Witness 从短暂状态文字升级为可保留、可展开的任务行动记录。
- 新增长命令观察：发现长时间无进展时提醒 Main Agent 调整策略，到达上限后清理进程树并留下证据。
- 强化 Task/Turn 作用域，避免新任务或一句“你好”继续执行其他任务的未完成工作。
- 修复停止任务后恢复按钮失效、重试残留旧 UI 与陈旧活动 Run 占位问题。
- Anchor 继续提供逐轮 Diff 预览、版本检查、冲突检测与安全回退。

### 6. 本地沙箱与桌面能力

- Docker 不再是命令执行的前置条件：未启动 Docker 时自动使用本地临时工作区沙箱。
- 本地沙箱会过滤敏感环境变量、约束工作目录、限制命令长度与时间，并在同步前执行冲突检查。
- Docker 仍可作为可选的更强离线隔离层，提供只读系统、能力剥离与资源限制。
- 新增隔离 Playwright Browser Runtime、视觉代理、工作区文件 `@mention`、长提示折叠、稳定实时 Agent 状态、任务耗时和系统托盘后台执行。

## English highlights

### Native renderer and explicit lifecycle

- Native React conversation runtime, a single-source TaskStore, pure Harness reducers, and an explicit run/turn coordinator replace migration-era state bridges.
- Provider streaming, permissions, tool dispatch/execution, workspace safety, conversation normalization, subagent execution, and progressive self-check are now isolated testable runtime modules.
- Batched streaming and deferred persistence reduce hot-path renderer churn.

### Unified extensions and capabilities

- Native, Office, Browser, Skill, and MCP tools share one Capability Registry.
- A bilingual Extensions center provides discovery, configuration, lifecycle controls, source policies, and permission presentation.
- Declarative Skills and trusted local/remote MCP servers can add scoped capabilities to a run.

### Safer multi-agent work

- Adaptive budgets keep simple conversations lightweight while complex tasks can use bounded Explore, Builder, Review, Verify, Curator, and Witness roles.
- Progressive review is version-matched, supports bounded parallel workers, and only seals current verification evidence.
- Curator autonomously decides whether evidence is durable enough for shared Project Understanding.

### Observable execution and recovery

- Witness preserves live progress and identifies commands that have stopped making progress.
- Task/turn context isolation prevents unrelated unfinished work from leaking into another conversation.
- Stopped-run recovery, retry cleanup, and per-turn Anchor rollback are more reliable.

### Practical sandboxing

- Commands work without Docker in a conflict-checked temporary local workspace.
- Docker remains an optional stronger offline isolation backend.
- Browser, vision proxy, workspace mentions, stable live status, prompt folding, tray execution, and Windows completion notifications are included.

## Validation / 验证

The release gate includes the production Vite build and focused smoke tests for Runtime, TaskStore, conversation isolation, run/turn lifecycle, streaming, capabilities, permissions, Browser, MCP, Skills, extensions, Understanding automation, self-check coordination, sandbox/Witness watchdogs, and the v0.6 architecture freeze.
