## @ 使用方式

| 输入 | 内容与限制 |
| --- | --- |
| @src/main.js | 授权工作区内的显式文件 |
| @{文档/使用说明.md} | 中文或带空格路径 |
| @src/main.js:10-30 | 指定行范围，附行号 |
| @src/ | 目录清单，最多 200 项；不递归附上文件内容 |
| @skill:名称 | 显式选择已安装 Skill |
| @mcp:服务器ID | 显式选择已配置、启用的 MCP |
| @git:changes | 当前工作区的已跟踪改动摘要；未跟踪文件只列名称 |
| @git:staged / @git:status | 暂存改动或状态，可直接输入 |
| @browser:会话ID | 当前任务已打开网页的一次只读快照；通过候选选择 |
| @terminal:会话ID | 当前任务已有终端/进程输出；不执行新命令 |

文件引用保持最多 8 个、单文件 256 KB、累计文件读取 640 KB 的边界；明确提示无法内联或截断情况。路径不能越出工作区，拒绝链接路径组件。任务快照有独立长度限制，失效/跨任务资源不会被读取。

显式引用的内容会作为本次请求上下文发给所选模型；这不是后台整库上传，也没有恢复手机同步、文件云端传输通道。浏览器一次快照不会把操作控制权移交给模型。

## 保留的边界

- 不自动执行第三方 Skill hooks，不声称兼容所有其他 Agent 宿主的私有元数据。
- MCP 保持 stdio / Streamable HTTP；没有擅自增加 OAuth、旧版 SSE 或新的外部账户授权流程。
- 网页引用只针对当前任务已打开的页，不自动抓取任意网址；侧边轻量聊天仍保持自身只读合同。
- 测试证明本地调用协议和恢复链路，不等同于所有外部 MCP 服务、真实模型或已发布安装包的验证。
- 本轮依据已批准的问题清单直接实施，遵循 spec-workflow 的明确范围路径及 web-development 的变更安全、实际浏览器验证要求；没有跨过部署门禁。
