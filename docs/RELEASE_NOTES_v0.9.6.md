# AporiaX 0.9.6 本地交付说明

2026-09-15。本次生成 Windows x64 安装版与便携版，未提交或发布 GitHub。

## 本版完成

- 超链接：修复中文、emoji、空格、括号、重复解码导致的截断/错误路径；校验工作区交付文件，不再因为坏链接触发额外模型循环或把整个任务判失败。
- Safe 依赖：不再链接到宿主的可写 `node_modules`。依赖使用独立副本，内部包链接重定向到副本；外部链接、循环和超限复制拒绝执行。普通脚本、项目脚本和离线安装均有回归。
- 异常恢复：冲突、取消、超时、非零退出和回写失败后保留快照；任务回复与失败卡片给出恢复链接。任务设置新增“沙箱恢复目录”，重启后仍可打开。
- 回写保护：跨工作进程同步锁、源文件冲突复核、原件备份、逐文件原子替换、磁盘同步请求与恢复日志；中途失败只回退仍与本次写入一致的文件，不覆盖用户的后续修改。
- 资源限制：流式文件哈希；副本默认最多 2 GiB（按可用空间进一步收紧），依赖文件/目录数量及递归深度有限额；恢复区同时保留/运行的快照上限 20 个，达到上限要求整理，不自动删除用户产物。

## 恢复产物怎么用

点击任务中的“查看保留产物”，或打开“任务设置 → 沙箱恢复目录”。桌面版默认位置：应用用户数据目录下 `aporiax-local-sandbox`。

每条记录包含：

- `recovery.json`：关联的任务/运行、状态、基线哈希和回写记录；若是正常执行后才发现的异常，还会记录错误/退出状态。
- `workspace/`：运行使用的独立副本，检查并复制所需产物。
- `before/`：准备回写的原文件备份；没有进入回写准备阶段时可能不存在。
- `pending/`：暂存的待应用文件；没有进入回写准备阶段时可能不存在。

不要直接用整个快照覆盖原工作区。先比较文件及日志，优先复制到新目录。状态 `executing` / `applying` 可能是正在运行，也可能是进程异常退出留下的记录；确认任务不再运行后再整理。`.locks` 是内部同步锁目录，不是产物。

本版提供目录、原件、日志和可点击入口，尚不是完整的逐文件图形化恢复向导，也不会在重启后自动回放未完成事务。

## 权限与能力边界

Safe 仍运行宿主进程，使用宿主网络和用户权限。独立依赖副本修复的是已知共享写入路径，不是 OS 级隔离；显式绝对路径、外部工具等宿主能力不能靠副本保证拦截。

依赖修改不会回写到原 `node_modules`。如需在真实项目安装依赖，应选择合适的执行配置；不要把副本安装成功误认为宿主依赖也已安装。

默认执行模式与全自动审批设置保持不变；不会为了此修复新增每条命令确认。Docker 未就绪时隔离模式仍拒绝降级到 Host。

本轮未完成：Docker 可回滚写层、MCP/Skill 统一隔离路由、隔离环境长期服务器、Windows 原生隔离。真实断电下的硬件持久性保证未测试；已测试的是进程终止留下的可恢复快照与回写日志，逐文件替换不是跨文件系统的 ACID 事务。
