# 团队消息 V1

用户确认按第一版方案实现，仅本地开发，不发布。沿用 Electron / React、已有聊天模型菜单与主任务调度。

## 验收范围
- 工作室「团队消息」及工位「聊一聊」打开右侧栏；列表置顶工作群，列出主管及自定义/内置角色。
- 当用户普通发消息时，只产生独立聊天回复，不执行文件/命令/角色管理或修改工作流。
- 群聊默认主管；用户显式 @ 选择最多 3 位，每位至多一次逻辑请求，不自发继续讨论，不自动重试。
- 项目/账号隔离聊天历史；无工作区任务独立。选择项目内任务作为只读证据来源；不跨项目访问。
- 角色删除后保留只读历史；禁用角色不得因聊天自动启用。角色实例不等于长期角色。
- 持久保存历史、未读游标、模型/Token/时间信息；停止只取消聊天请求。没有计价就不虚构金额。
- V1 每个会话保留最近 300 条消息，模型上下文最多引用最近 10 条（每条最多 1600 字）；这是聊天记忆，不是任务执行记忆。
- 「转为工作要求」必须编辑预览并确认，交给当前任务主管协调，沿用现有工作权限。

## 界面设计
柔和圆角的 iOS 风格通讯录；右侧非对称停靠，与工作室并列。列表和聊天同一面板内切换。
复用品牌 token：白 #ffffff、浅灰 #f3f5f9、夜间近黑 #0f1113、蓝 #1a7acb；实际颜色跟随全局主题。
字体沿用已批准 --font-sans（Inter / Segoe UI / Microsoft YaHei），14px 正文、12px 辅助信息；不引入新字体或 Tailwind。
沿用 Lucide 图标、办公室角色皮肤。日夜只换配色，不换尺寸；输入区为随多行文字伸展的圆角胶囊。
常驻只保留头像、对象标题、聊天内容及输入区。列表搜索收进搜索按钮；工作背景、模型收进顶部「聊天设置」；时间、用量、依据和转交收进每条消息的「消息选项」（悬停/键盘聚焦可见，触屏直接可见）。
群聊保留发言者名字和显式 @ 对象；私聊不重复名字。异常和只读状态仍然明示，不因简化界面隐藏。转交仍需编辑预览与确认。
消息轻微入场、等待点动画遵循系统减少动态效果偏好。未修改模型调用、角色权限、存储和工作任务行为。

## 实现与校验
独立本地 team-chats 服务：可信 IPC、宿主解析项目范围、只读角色工作证据、无执行工具、受限模型调用。
复用现有 provider 适配器，允许单次请求策略；保留默认工作任务重试策略不变。
群聊按用户选择顺序回复；只投递当前群历史与接收角色相关工作记录，限制上下文和输出。
不会后台唤醒角色；自动群通知/跨任务通知中心不在 V1，后续再接入。
验证：服务隔离/并发/取消/错误/持久化/未读/删除角色；浏览器流程/窄宽/主题；真实 Electron IPC 与入口，无付费请求。
