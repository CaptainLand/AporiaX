# 正式版安装：目录选择与整理安装副本

这项功能随 **1.0.0 正式版安装器**提供，而不是依赖旧客户端增加代码。因此旧 RC 客户端下载并运行该正式版安装器时，也可以使用。是否整理以及处理哪些副本始终由安装时的确认决定；发布构建本身不会清理开发机器上的真实安装。

## 安装目录

- 首次安装选择父目录，例如 `D:\软件`，实际安装到 `D:\软件\AporiaX`。
- 选择的目录已经叫 `AporiaX` 时，不再重复追加。`AporiaXTools` 等包含相同文字但不同名的目录仍会追加一层。
- 整理页可更改安装目录，选择一个新位置后再整理原位置。默认保留正在更新的已知位置；不会因为一个旧副本的登记而强制退回默认 C 盘目录。
- 非空目标目录必须能确认是 AporiaX，不能将其他资料目录直接当作程序目录覆盖。不会降级覆盖更高版本。

## 整理流程

1. 读取当前产品的原始安装/卸载登记、可访问的 AporiaX 卸载记录、桌面/开始菜单快捷方式及常见安装目录。不会全盘扫描，也不会扫描其他用户的资料目录。
2. 展示每份副本的目录、版本与处理说明。可确认且版本不高于本次正式版的旧版/重复副本默认勾选。未登记目录可手动添加。
3. 用户确认保留位置和待整理列表；也可选择“仅安装，不整理”。正在运行的旧版需要从托盘退出，再点“重新检查”，不强制结束进程。
4. 安装前重新核对确认计划的 SHA-256、目标目录和链接边界。临时抑制旧安装器的自动卸载调用，避免在新版落地前执行另一份旧程序的卸载器；取消或安装失败恢复原登记值。
5. 新版文件落地后，核对产品名、程序/归档版本、应用入口以及归档的必要边界。**这是安装文件校验，不等同于真实启动及全部功能验收。** 校验失败时不清理其他旧副本。
6. 再次核对旧副本身份、确认时的程序/归档哈希、版本、运行状态及文件边界。只移动明确属于程序的文件，更新匹配的现有桌面/开始菜单快捷方式，清理仍指向成功整理副本的本产品登记。

## 保留与恢复

- 旧程序移入当前用户的 `%LOCALAPPDATA%\AporiaX\installation-backups\日期-随机编号`，不会永久删除整个旧文件夹。
- 每份备份有 `restore-manifest.json`，总报告为 `report.json`；记录原目录、备份位置、完成/跳过情况。元信息采用临时文件原子替换并保留上一份。
- 恢复时先退出 AporiaX，按清单将程序文件复制回原目录。不要直接覆盖正在运行的新版。
- 不动对话、账户凭据、用户配置、工作区、混放文档和不在程序清单里的文件。原目录还有额外文件时保留该目录，只清理已确认的程序文件。
- 文件锁定、链接/重解析点、范围重叠、确认后身份变化、版本更高、没有权限或无法识别的目录会跳过。文件移动中失败会尝试恢复已经移动的文件，剩余备份与报告保留；不承诺断电情况下的完整自动回滚。

## 安装方式边界

- `1.0.0` 等稳定正式版的交互安装默认提供此流程；RC、便携包和静默安装不自动清理。
- 无人值守安装没有用户确认，沿用旧目录保护逻辑。`--skip-organize` 可明确使用原安装流程。
- “全部清理”指本次明确确认、可安全识别和处理的副本，不承诺发现所有磁盘上的任意手动复制文件夹。更高版本、其他用户安装或无法处理的副本不会冒险删除。
- 正式版必须重新构建安装器后发布；已经下载的旧 RC 安装包不会自动获得此功能。
