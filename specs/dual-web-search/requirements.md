# AporiaX 双通路联网搜索需求

状态：2026-10-22 用户确认“现在就开始做，用 OpenCode 的方法”，直接实施；仅本地开发，不发布。

后续授权：2026-10-22 用户确认将联网工具及本轮 UI 一并打包、推送并正式发布 1.0.6；先前的“仅本地”限制对这些已确认改动解除。个人 ChatGPT／Codex 实验接入仍不开放，不变更公共额度池或云端模型服务。

## 问题与目标

目前 AporiaX 已有浏览器打开网页、读取页面和交互的工具，但缺少独立的广搜索入口。普通检索依赖浏览器操作，难以快速发现并比较多个来源。

新增内置 `web_search` 和轻量 `web_fetch`，与现有浏览器工具并存。AporiaX 可按任务自主选择和组合三种能力，用户无需手动切换搜索模式。复用 OpenCode 的职责划分，不引入 OpenCode 应用或完整研究 Agent。

## 首版范围

- 广搜索：直接返回多个来源的标题、链接和摘要，不打开或抢占侧栏浏览器。
- 网页读取：读取公开链接正文，分段返回，不占用侧栏浏览器；明确区分 HTTP 文本、第三方提取与真实浏览器验证。
- 深入浏览：保留现有浏览器工具，适合读取原文、动态页面、交互及实际页面验证。
- 可先广搜再打开部分来源，也可直接打开用户提供的链接；不强制固定步骤。
- 搜索能力独立于具体模型供应商，不改变现有模型、计费及个人账号接入。
- 在现有工具记录中显示搜索进度、结果与失败原因，不新增复杂的搜索控制面板。

## 用户故事与验收标准

### R1：快速发现多个来源

作为用户，我希望 AporiaX 能直接检索网络，而不是每次都在浏览器搜索框中操作。

- 当调用广搜索时，系统应接收一条查询和可选目标，默认返回 5 条、最多 8 条结果，并限制单次返回文本量；模型可并行发起独立查询，不设置累计搜索轮次上限。
- 当搜索成功时，系统应保留每条有效结果的标题、HTTP(S) 链接和可用摘要；日期只有来源确实提供时才显示。
- 当同一链接重复出现时，系统应合并重复结果并保留与查询的对应关系，不虚构缺失信息。
- 当搜索执行时，系统不应打开、切换或导航用户的侧栏浏览器。

### R2：两种工具自主调度

作为用户，我希望 AporiaX 按任务选择广搜或浏览器，也能配合使用。

- 当任务需要发现来源或比较多个页面时，模型应能选择广搜索。
- 当任务已有明确链接，或需要阅读全文、动态内容和网页交互时，模型应能直接选择现有浏览器工具。
- 当搜索摘要不足以支持重要结论时，模型应能进一步打开来源核实，而不是将摘要当作页面验证证据。
- 当执行角色已有工具权限限制时，新增搜索不应扩大该角色原有授权；允许联网的角色可在其授权范围内使用搜索。
- 当需要追加检索时，系统不应因首版单次查询数量限制而禁止后续搜索；仍遵守现有任务停止与权限机制。

### R3：可取消、失败透明

作为用户，我希望搜索不会卡住任务，失败时能改用浏览器。

- 当用户停止任务时，系统应取消正在进行的搜索请求并释放连接。
- 当搜索服务超时、不可达、限流或返回无效响应时，系统应返回准确、可操作的错误，不伪装成零结果或成功。
- 当搜索失败且浏览器仍被授权时，模型应能选择浏览器继续；不得无上限自动重试。
- 当并行查询中某条失败时，系统应通过现有工具记录保留各调用的独立结果，不把错误伪装成零结果。

### R4：来源与安全边界

作为用户，我希望搜索可追溯，也不会把本地资料擅自发送给外部服务。

- 当调用搜索服务时，系统应只发送必要的查询及搜索参数，不自动附带本地文件、完整会话、账号凭据或浏览器 Cookie。
- 当搜索结果包含指令或要求提升权限时，系统应将其作为不可信网页内容，不执行或赋予指令权限。
- 当现有联网或工具权限禁止操作时，系统应拒绝搜索，不借新增工具绕过限制。
- 当生成有来源依据的回答时，模型应能引用真实结果链接；搜索摘要不等同于已阅读全文或实际验证。
- 当记录工具调用及异常时，系统不应输出服务密钥或授权头。

### R5：轻量网页读取

- 当读取普通公开网页时，系统应只发起只读请求，不携带用户 Cookie、浏览器登录态或认证信息，不执行本地浏览器脚本。
- 当直接连接时，系统应校验域名解析的全部地址，固定已校验地址，并逐跳校验重定向；拒绝内网、凭据 URL、保留地址、非标准端口和 HTTPS 降级。
- 当网络将公开域名解析为 198.18/15 代理虚拟 IP 时，系统不得连接该保留地址；允许改用同一 Exa 服务提取公开 URL，显式标记来源及可能的缓存/省略。
- 当响应为二进制、超大内容、异常状态或不完整传输时，系统应报错，不下载或声称已读全文。
- 当正文超过返回预算时，系统应给出续读位置；缓存仅限本轮，限量、过期、任务结束清理。

## 搜索服务：已确认 Exa 首版

首版采用 Exa 官方托管 MCP 的匿名搜索模式，封装为 AporiaX 内置工具，不要求用户手动安装 MCP。复用项目现有 MCP SDK；可由启动环境提供 EXA_API_KEY，不从项目指令或模型参数读取密钥。匿名模式存在限流；不承诺无限额度、永久免费或任何网络环境下可用。

需实际验证本机连通性、协议兼容性、结果字段及取消行为。不得为验证擅自创建账号、购买套餐或申请付费服务。搜索来源封装在独立适配器中，为以后替换预留边界。

官方依据：

- [Exa MCP 接入说明](https://exa.ai/mcp)
- [Exa 官方仓库：工具与匿名限流说明](https://github.com/exa-labs/exa-mcp-server/blob/main/README.md)

## 非目标

- 本轮不发布桌面端、Web、云端服务，不接公共额度池。
- 不替换现有浏览器，不新增自动登录、验证码绕过或代理服务。
- 不新增付费搜索账号、自己的云端搜索代理、SearXNG 服务或新的浏览器运行环境。
- 不把搜索到的网页内容自动作为可执行操作或可信系统指令。

## 验证项目

公开/内网边界、DNS 固定与重定向、超时取消、HTML 提取、Exa 当前参数/返回格式、原生目录与能力展示、角色与父权限上限、禁用联网时实际拒绝、无工作区检索、真实搜索及当前代理网络下的网页读取、生产构建、依赖增量。
