# 本地验证记录：额度续跑与头像 UI 暂停

日期：2026-09-25。以下主体为此前本地阶段记录；用户现已批准打包、部署和 GitHub Release。Preview 6 发布准备结果见末尾，不把本地测试当作线上验收。

最新修订采用用户确认的「实际扣费、允许负额度」方案，替代上一轮按个人余额压缩输出的方案。

## 已实现

- 网页顶部账户按钮仅保留昵称；账户中心隐藏头像及上传/移除编辑入口。授权页面不再展示用户上传图片。
- 桌面左下角账户入口及弹出菜单恢复默认账户图标，保留昵称、额度和账户中心功能。
- 两端通过默认关闭的构建开关 `VITE_APORIAX_PROFILE_AVATARS` 暂停头像 UI。组件、编辑器、校验逻辑、服务端接口和已有头像数据保留；隐藏操作不会删除或重新上传头像。
- Cloud 个人额度不再预占。只要已结算余额大于零就允许调用，不按个人余额缩小最大输出；余额小于估算输入费用也不会因此拒绝。
- 实际用量允许扣成负余额；周额度允许实际已用量超过赠送量，并保留带正负号的剩余额度。零金额记账凭证仅用于请求关联、恢复和防重复扣费，不冻结资金。
- 余额到零或负数后，新请求及已准入但尚未派发的请求均会被拦截。最终派发确认与实际结算串行校验，避免排队请求漏过停止条件。
- 桌面收到已结算的耗尽收据后，先保存完整响应再暂停，尚未交付执行的工具不会继续。恢复及重启使用已保存响应，不再生成或重复扣费；截断内容仅保存有效部分，不执行不完整工具参数，也不因额度耗尽自动翻倍重试。
- 已经派发的并发请求仍正常结束并如实结算，因此可能继续增加负额度。只有保留的全站每日费用保护仍会等待服务商在途成本结算；该等待与个人额度耗尽明确区分。
- 周额度、服务端配置的每日费用上限、防重复扣费、未知费用核对和已有权限检查保留。自带 API 流程不变。

## 边界与后续

- 服务商在响应结束时才提供实际用量，所以停止边界是结算耗尽后的新派发，并非逐 token 恰好零余额时强断。既有并发、单次输出及全站费用保护仍限制在途风险，但不保证负额度固定为某个小数值。
- 个人余额为正就可发起调用；为零或负数必须先恢复正余额才能发起下一次新调用。周额度跨周期仍按既有重置规则，超额保留在原周期记录中。
- 未知或不确定的已付费请求继续走核对保护，不会被自动当作额度等待重新生成。
- 保存的是已确认的对话、工具结果、文件和部分输出，不承诺恢复服务商内部不可见的推理状态。
- 线上网站、Cloud 服务和已安装桌面版本尚未改变；本地源码修改不是已上线修复，仍需后续明确批准部署及打包。
- 采用规格流程记录允许负数和及时停止的明确边界，测试覆盖新旧协议及保留的安全检查；不做额外 UI 重设计。
