# qq号锐评b50

用户给出 QQ 号或水鱼用户名，要求「查 b50 / 锐评 / 点评 / 给提升建议」时执行本流程。
不适用于：需要上传成绩（要 token）、需要私密成绩、需要打歌视频或谱面分析。

## 一、取数：只走脚本，不要手写请求

这是 AporiaX 出厂内置技能。只有用户明确要求公开 B50 查分、锐评或提升建议时才调用；普通对话不加载、不查号。仅有 QQ 号但意图不明时先询问，不自动联网。

`<SKILL_DIR>` 使用激活信息中的 `Node script root`，没有该行时才用 `Package root`。这是实际文件目录，不是需要用户配置的环境变量。安装包会解包此脚本，不能让系统 Node 直接执行 `app.asar` 内路径。目录含空格时必须整体引用脚本路径。脚本仍须通过 `run_command` 的正常权限与网络边界；没有网络权限就如实说明，不绕过沙箱或审批。

默认用 `--md --no-table` 输出摘要以节省上下文。只有用户要求保存数据时才用 `--json`，输出限定在当前任务工作区；不要写入 Skill 安装目录，也不要请求上传成绩所需的私人 token。

```bash
node "<SKILL_DIR>/scripts/fetch-b50.mjs" --qq 123456789 --md --no-table
node "<SKILL_DIR>/scripts/fetch-b50.mjs" --username CaptainLan --md --no-table
node "<SKILL_DIR>/scripts/fetch-b50.mjs" --qq 123456789 --json b50.json   # 只落盘不打印
```

脚本已封装真实端点，端点写死，不要自行改路径：

- `POST https://www.diving-fish.com/api/maimaidxprober/query/player`
- body：`{"qq":"<QQ>","b50":true}` 或 `{"username":"<用户名>","b50":true}`
- **不要用 `/api/query/player`**，该路径返回 nginx 404，不是接口错误。

错误响应处置：

| 现象 | 含义 | 怎么做 |
|---|---|---|
| 400 `{"message":"user not exists"}` | QQ 未绑查分器 / 用户名错 | 让用户确认 QQ 与绑定状态，不要换参数硬猜 |
| 403 | 账号关闭了公开查分 | 说明需本人开启公开成绩，不可绕过 |
| 网络失败 / 非 JSON | 服务或网络问题 | 如实报告失败，**绝不编数据** |

## 二、字段口径：先读这一节，历史事故都在这里

`fc` 字段只有四个真实取值，外加「空字符串＝未标注」，**AP+ 的唯一写法是 `app`**（不存在 `appx`、`ap+` 之类变体）：

| 取值 | 含义 | 硬性条件 |
|---|---|---|
| `app` | AP+ | 全部 CRITICAL PERFECT |
| `ap` | AP | 全部 PERFECT 及以上，无 GOOD/MISS |
| `fcp` | FC+ | 零 MISS，且 BREAK 全 CP |
| `fc` | FC | 零 MISS |
| 空字符串 | **未上传标注** | **不等于没有 FC，不可推断判定水平** |

`fs` 是 SYNC 标记（`fs`/`fsp`/`fsd`/`sync`），与 `fc` 独立，不要混列。历史上曾把 `fcp` 误标成 AP+ 并写满整张表，导致「一堆 AP+」的错误结论；判定列**必须**叫「判定」，不要用 `MA` 之类会与 MASTER 混淆的列名。

难度：用 `ds` 做数值计算，用 `level_label`（或 `level_index`：0 BASIC / 1 ADVANCED / 2 EXPERT / 3 MASTER / 4 Re:MASTER）做展示。`level` 字段是 "14+"/"15" 这类分组标签，不能参与运算。

`ra` 复算公式（与接口逐条核对过，50/50 精确复现）：

```
coef(ach) 按达成率取档：>=100.5→22.4, >=100→21.6, >=99.5→21.1, >=99→20.8,
>=98→20.3, >=97→20.0, >=94→16.8, >=90→15.2, >=80→13.6, >=75→12.0,
>=70→11.1, >=60→9.6, >=50→7.2, >=40→5.0, >=30→3.2, >=20→2.0, >=10→1.0, 其余 0
ra = floor(ds * coef * min(ach, 100.5) / 100)
```

由此可推出的关键事实，写锐评时要用：

- **rating = 旧曲 Top35 + 新曲 Top15 的 `ra` 之和**，与 FC/AP 标记完全无关。AP+ 不额外加分。
- 达成率上限 101%，其中 BREAK 全 CP 最多贡献 +1%；所以 100.8% 完全可能是 FC+ 而非 AP。
- 达成率 ≥100.5% 时系数封顶 22.4，**再往上只能靠裸达成率**，系数红利已经吃完。

## 三、数据校验（强制，不通过不许写锐评）

脚本会打印校验块，必须全部满足：

1. 旧曲 ≤35、新曲 ≤15，条数与 b50 上限的关系合理；
2. `ra` 合计 **严格等于** `rating`；
3. 公式复算与接口 `ra` 不一致条数为 0。

任一项不满足：重取一次；仍不满足就**如实写明接口只返回了 N 首、缺口多少 ra**，禁止从记忆里补曲名、补成绩、补一行「合计对得上」。历史事故就是这样把 25 首写成 35 首的。用户质疑数据时，先重新拉取核对，再明确说明是哪一次错、错在哪一条，不要只改口径不改证据。

## 四、锐评：结论先行，每条挂数字

固定五段，不要写成流水账：

1. **一句话定性**：用最扎眼的结构性事实，句式短，不堆形容词。
2. **判定构成表**：AP+ / AP / FC+ / FC / 未标注 五档计数，旧曲新曲分列。空标记单独点名，说明是数据缺失。
3. **4~6 条观察**，每条格式为「断言 → 具体曲目或统计量 → 为什么」。合格例子：某首 14.9 达成率仅 100.57% 却给 335，而另一首 14.8 打到 100.80% 只有 333，说明账号在精算定数而非精进精度。不合格：泛泛说「你的精度有待提高」。
4. **结构性反差**：新曲 vs 旧曲的平均达成率与定数、ra 分布集中度、定数与达成率的背离、Re:MASTER 数量与 AP 数量的落差。挑最有信息量的一到两个。
5. **收尾一句**，不写鼓励、不写「继续加油」。

分寸：犀利打的是成绩结构与选曲策略，不攻击人。允许刻薄，不允许无据；每条断言都要能指回某一行谱面或某个统计量。不要复述脚本已经打印的整张 50 行表，正文只贴判定构成和关键行，完整表放折叠或按需给。

## 五、建议：先算账，再给动作

脚本输出四个候选池：A 跨系数档、B 每首 +1 ra 成本、C 天花板余量、D 定数结构瓶颈。建议固定三条，按可用性取池：

1. **马上能拿的分数**：A 有货就优先 A（跨档收益最大）；A 为空说明达成率全部 ≥100.5%，系数红利已吃完，要明确说出来。B 或 C 有可行项时给具体曲目、目标达成率、需要多少 pp。**B/C 为空时说明原因（每首已达公式上限），不要输出空表糊过去。**
2. **结构性出路**：拿 D 池的榜尾替换估算，指出该去开哪些更高定数的谱面、上限能加多少 ra。必须标明这是上限估算，不是承诺；新曲池 ds 上限通常低于旧曲池。
3. **止损**：点明哪些池子不值得再投（已封顶且已 AP 的曲子、定数偏低的新曲池），把练习时间导到收益更高的地方。

每条建议都要带可验证的数字：目标 ra、收益点数、达成率门槛、需要补的曲目定数。禁止「多练」「提升稳定性」「注意节奏」这类无法执行的建议。

## 六、输出契约

- 中文 Markdown，表格用 GFM。
- 结尾固定一行：`数据校验：旧曲 A 首 + 新曲 B 首 = N 首，ra 合计 X == rating Y`。
- 不倾倒原始 JSON，不展示请求体与调试日志。
- 数据来源标注为水鱼查分器公开接口；若返回 403 说明对方已关闭公开成绩。
